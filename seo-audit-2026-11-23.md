# SEO audit: mtdsoftwarecompare.co.uk

Date: 23 November 2026 (Europe/London).  
Live site audited first (curl + Python, equivalent to [Seobility's on-page checker](https://www.seobility.net/en/seocheck/check/)). Seobility's own free quota was used up from this IP; D later shared a homepage result of **63%**.  
This file records the findings, what was fixed in the generator, and what was left alone.

Pixel limits follow Seobility: **title 580px** (Arial/Liberation Sans ~20px, calibrated so the pre-fix homepage title matches Seobility's 698px), **meta description 1000px** (~14px).

Nothing was sent to Google or Bing as part of this work. The site was not force-pushed.

## Real problems (and the fix)

1. **Titles over 580px** — 192 of 200 built pages, including the homepage (698px). Google and Seobility truncate these.  
   **Fix:** `head()` in `build.py` now runs every title through `scripts/seo_width.py` (`fit_title`, 580px). Homepage, kit, Do I need MTD?, product pages and guide `meta_title` values were rewritten to fit. Long product names keep “for MTD \| MTD Software Compare” when it fits, otherwise “{name} \| MTD Software Compare”, and only drop the brand if the name itself is too long (for example FreeAgent for free with Mettle, NatWest & RBS). Guide H1s stay long and descriptive; the document title uses the shorter `meta_title` or `short` name.

2. **Meta descriptions over 1000px** — 80 pages, including the homepage (1050px) and a long product-page template.  
   **Fix:** `fit_desc` (1000px) in `head()`, plus shorter templates and a `meta_description` on each guide. Product descriptions are now: “Is {name} HMRC-recognised for MTD? Yes. See price[, checked {date}], free version and key features in plain English.”

3. **Words from the homepage H1 not found in the text** — flagged by Seobility. The hook “in 30 seconds” did not appear in the body.  
   **Fix:** H1 is “Find your MTD software in 30 seconds”. The intro is “Answer three quick questions and find your MTD software in 30 seconds. 179 HMRC-recognised products are listed below.”

4. **Duplicate heading texts** — Popular picks and Featured (and the finder-match cards in `funnel.js`) all used the product name as an `<h3>`, so four featured products appeared twice as headings.  
   **Fix:** those card names are now `<p class="pcard-name">`. Section headings stay: Popular picks (h2), Featured MTD software (h3), Best of the rest (h3). Styling is unchanged.

5. **No favicon markup, and `/favicon.ico` 404** — flagged by Seobility.  
   **Fix:** green brand-colour mark with a white “M” at `/favicon.ico`, `/assets/favicon.svg` and `/assets/apple-touch-icon.png`, with `<link rel="icon">` and apple-touch tags in `head()` so a rebuild keeps them.

6. **Keyword consistency for “MTD software”** — the old title had “Making Tax Digital software” (good) but the description did not use the exact phrase “MTD software” or “Making Tax Digital software”.  
   **Fix:** the new title, H1, intro and description all use “MTD software”.

These limits, favicon markup, “no duplicate headings”, and the homepage H1-in-body rule are now enforced by `scripts/check_site.py`.

## Minor findings (not treated as must-fix)

- **No `og:image` or Twitter image.** Social shares will have no preview image. A designed share card would help, but Seobility did not flag this as a title/description/heading issue and inventing a one-off graphic was out of scope for this pass.
- **Homepage HTML is large** (~262 KB uncompressed, ~21 KB gzipped). Almost all 179 products are in the page and in a large ItemList JSON-LD block. Gzip is on; TTFB from this network was about 0.4s. Shrinking this means a redesign of the directory, not a meta-tag fix.
- **Render-blocking CSS.** `/assets/style.css` (~20 KB) is a normal render-blocking stylesheet in the head. Too small to justify a rewrite.
- **Sitemap `lastmod` dates** on some key pages (including the homepage, still dated 18 November 2026 in the sitemap at audit time) lag later content updates. Minor; not part of the Seobility homepage flags.
- **Some product titles omit the brand suffix** when the product name itself is already long, so the title stays under 580px. Better than a truncated SERP title.
- **HTTP (port 80) → HTTPS could not be verified** from this environment: the egress proxy returns HTTP 500 to all port-80 requests. HTTPS itself is fine (Let’s Encrypt, valid until 19 February 2027, covers apex and www). `https://www.mtdsoftwarecompare.co.uk/` 301s to `https://mtdsoftwarecompare.co.uk/`. GitHub Pages usually also redirects HTTP when “Enforce HTTPS” is on; worth a quick check from a phone if you want certainty.
- **Guide and kit H1s** are still long (on-purpose, for readers). Only the `<title>` and meta description were shortened. A few H1 words (for example “really”, “rules”) do not appear in the body; that is not the homepage issue Seobility reported, and the H1s were left as they are.

## What already passed (pre-fix, and still true)

- HTTPS, valid certificate, apex canonical.
- `https://www` → non-www 301.
- `html lang="en-GB"`, charset UTF-8, viewport set.
- One H1 on the homepage; heading levels do not skip (h1 → h2 → h3).
- Canonical tags present and self-referential.
- Robots meta `index,follow,max-snippet:-1` on indexable pages; noindexed product pages are kept out of `sitemap.xml`.
- Open Graph basics: `og:type`, `og:title`, `og:description`, `og:url`, `og:site_name`, `og:locale`, plus `twitter:card` = summary.
- JSON-LD on the homepage (WebSite, ItemList, FAQPage) and product/guide pages parses.
- `robots.txt` and `sitemap.xml` return 200; sitemap lists 50 URLs (core pages, guides, and the indexable product pages, not all 179).
- Custom 404 returns **404**, with `noindex,follow`, a clear H1 and a link home.
- Homepage word count is high (thousands; well above any “thin page” floor), driven by the full directory.
- Kit preview images (where used) have alt text. The homepage itself has no `<img>` tags, so no missing-alt issue there.
- Analytics script is deferred; internal JS is deferred.
- Only the public contact email appears on pages.

## External / ignored (as agreed)

- Seobility “domain is long” — ignored.
- External factors / backlinks at 3% — ignored. That score moves with links from other sites, not with on-page edits.
- Directory listings (FreeIndex, Cylex, Yell, Hotfrog) were already blocked from this computer; not part of this SEO-code pass.

## How the limits are kept

- `scripts/seo_width.py` — dependency-free character widths, Seobility-calibrated.
- `build.py` `head()` — applies `fit_title` / `fit_desc` to every page, including a future long product name.
- `scripts/check_site.py` — fails the build if any page exceeds 580px / 1000px, is missing favicon markup, has duplicate heading text, or if the homepage H1 words are missing from the body.

After the rebuild, 199 `index.html` pages: title max ~580px, description max ~983px, 0 checker problems.
